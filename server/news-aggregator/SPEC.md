## Почему не «точная копия» модели SmartCargo

В SmartCargo источник — собственные Telegram-каналы компании, поэтому там осознанно
хранился и рендерился **полный текст** новости, а ссылка на источник намеренно
скрывалась от публики (см. `news-public/HANDOFF.md` того проекта).

Здесь источники — чужие СМИ и официальные сайты. Копировать статьи целиком и
показывать без ссылки на автора — репутационный и авторско-правовой риск. Поэтому
модель для BROK работает как агрегатор (по образцу Google News / RSS-читалок):

- храним **заголовок + краткое резюме (excerpt)**, которое пишет редактор в
  админке своими словами, а не парсер;
- **обязательно показываем источник и ссылку** на оригинал — и в API, и в
  мобильном приложении («Читать в источнике →»);
- полный текст статьи не копируем и не публикуем.

## Что реализовано в этом каталоге

Код в `src/` — это **парсер-заготовка**: скачивает HTML/RSS источника, вытаскивает
список кандидатов (заголовок, ссылка, дата, если есть — превью текста) и прогоняет
через фильтр релевантности. Дальше кандидат сохраняется как `DRAFT` и ждёт
редактора в админке (сам экран админки в этой спецификации не реализован — нужен
такой же по духу, как `news-admin` в SmartCargo, с вкладками Черновики /
Опубликованные / Отклонённые / Дубли).

**⚠️ Важно: селекторы не проверены на живой разметке.** Из песочницы, где писался
этот код, исходящие HTTPS-запросы к `alta-soft.kz` и `zakon.kz` блокируются
политикой сети (403 на уровне прокси). Позже это перепроверено ещё раз через
WebFetch (30.07.2026) на все три URL из таблицы выше — все три тоже вернули 403,
включая `eec.eaeunion.org`. Получить и посмотреть реальный HTML ни разу не
удалось. Структура источников в `src/sources/*.ts` основана на косвенных данных
(поисковая выдача, публично известные URL) и **написана как рабочая гипотеза с
понятными точками для правки**: CSS-селекторы вынесены в константы в начале
каждого файла. Первое, что нужно сделать на стороне бэкенда — открыть каждую
страницу в браузере, свериться с реальной разметкой и поправить селекторы. Без
этого шага перед продакшеном запускать нельзя.

## Юридическая оговорка

Перед регулярным запуском:
1. Проверить `robots.txt` каждого источника (`/robots.txt`) на предмет запрета
   обхода конкретных разделов.
2. Проверить пользовательское соглашение сайта на счёт агрегации/цитирования.
3. Для `EAEU` (eec.eaeunion.org) — это официальный государственный ресурс,
   цитирование новостей о своей работе, как правило, не ограничено, но точную
   формулировку лучше сверить.
4. Там, где условия неясны — писать в поддержку/редакцию сайта с вопросом о
   возможности агрегации по образцу RSS-читалки, либо ограничиться ссылкой без
   собственного резюме.

## Модель данных

```ts
type NewsSource = 'ALTA_SOFT' | 'EAEU' | 'ZAKON_KZ';
type NewsStatus = 'DRAFT' | 'PUBLISHED' | 'REJECTED' | 'DUPLICATE';

interface NewsItem {
  id: string;
  slug: string;               // генерится из title при публикации
  title: string;
  excerpt: string;             // черновик пишет парсер (лид/сниппет), правит редактор
  imageUrl: string | null;
  publishedAt: string;         // ISO, дата на источнике
  source: NewsSource;
  sourceUrl: string;           // прямая ссылка на статью — обязательна, наружу не скрывается
  status: NewsStatus;
  relevanceScore: number;      // 0..1, см. src/relevance.ts
  duplicateOf?: string;
  duplicateScore?: number;
}
```

Таблица `news` — переиспользовать структуру из SmartCargo (`slug`, `excerpt`,
статусы `DRAFT/PUBLISHED/REJECTED/DUPLICATE`, `duplicateOf`/`duplicateScore`), с
добавлением `source` и обязательным (не скрываемым) `sourceUrl`.

## Фильтр релевантности («таможня + деньги»)

Берём кандидата, только если заголовок/сниппет содержит слова из `src/relevance.ts`
(таможня, декларация, ВЭД, пошлина, тариф ЕТТ, НДС/акциз на ввоз, ИС «Кеден»,
СПОТ, ЕАЭС/ЕЭК, таможенный брокер/представитель, товарооборот, бюджет/доходы в
бюджет и т.п.). Строгий keyword-фильтр — сознательно простой первый фильтр;
если окажется, что пропускает мусор или режет нужное — заменить на
классификатор с более широким контекстом (в спеке не реализовано намеренно,
чтобы не городить ML-пайплайн без реальных данных для проверки).

## Дедупликация

`src/dedupe.ts` — грубое сравнение по нормализованному тексту заголовка
(Jaccard по словам). Как и в SmartCargo, дубль **не скрывается**, а помечается
статусом `DUPLICATE` с `duplicateOf`/`duplicateScore` — редактор решает сам.

## Публичный API (для мобильного приложения BROK)

```
GET /api/v1/public/news?page=0&size=12   -> { content: NewsItem[], totalPages, number }
GET /api/v1/public/news/{slug}           -> NewsItem
```

Отдавать только `status = PUBLISHED`. Поля отдаются как есть, включая
`sourceUrl` — здесь его скрывать не нужно (см. раздел выше).

Мобильное приложение (`src/screens/NewsScreen.tsx`, `NewsDetailScreen.tsx` в
корне репозитория) уже написано под этот контракт и падает на демо-данные
(`src/data/news/mockNews.ts`), пока `API_BASE_URL` в `src/data/news/api.ts` не
указывает на реальный бэкенд.

## Как проверено

Селекторы и структура источников — **не проверены на живой разметке** (см. раздел
про блокировку сети выше). Логика фильтра релевантности и дедупликации проверена
юнит-тестами на синтетических данных (`src/*.test.ts` — если добавите `jest`,
тестовых сценариев в этой заготовке нет, только сами модули). Мобильный экран
проверен только на демо-данных, реальный бэкенд не поднимался.

## Что нужно сделать перед запуском в проде

1. Свериться с реальной разметкой каждого источника, поправить селекторы в
   `src/sources/*.ts`.
2. Проверить `robots.txt` и условия использования (см. «Юридическая оговорка»).
3. Поднять хранилище (таблица `news`) и публичный API — либо на существующем
   бэкенде BROK, либо отдельным сервисом.
4. Сделать экран администрирования (по образцу `news-admin` SmartCargo) для
   вкладок Черновики / Опубликованные / Отклонённые / Дубли — сейчас его нет,
   есть только парсер, кладущий кандидатов в `DRAFT`.
5. Подключить `API_BASE_URL` в мобильном приложении.
